# Verification

Run `tools/Test-Foundation.ps1 -PesterManifestPath <independently-verified-Pester.psd1>` on Windows with the pinned PowerShell 7.6.6 and Pester 5.7.1. It checks syntax, schemas, module exports, dependency inventory and the complete offline/Windows suite. Hosted PR CI has no deployment credentials or privileged IIS runner.

Tests cover strict package/approval contracts, malicious archives, physical paths and access checks, exclusive locking, deployment, fresh-readiness NoOp, configuration restart, partial replacement, retained backups and all three explicit recovery modes. File/state/backup operations use owned NTFS fixtures; IIS and independent-identity observations are synthetic. Qualification-tool tests also use actual loopback Kestrel and current-user DPAPI. Passing these tests does not qualify a real IIS host or service token.

Application compatibility, consumer workflow/packaging checks and any compiled-application deployment bridge remain application-owned. For an authorized representative payload, measure deployment, backup and replacement time against the operation budgets in [public contracts](contracts.md). Local synthetic-IIS timing does not establish Server 2022/IIS throughput.

`AutomatedDeployment.Tests.ps1` covers centralized tag classification, protected standing policy, certificate/predicate mismatches, verifier/root/ZIP integrity, successive admission and NoOp, identity conflicts, revocation, interrupted publication, locking and independent recovery authority. It mocks only the verifier process launch with a bounded harmless process returning synthetic certificate/predicate data. Keep those negative tests; existing lifecycle/backup/readiness/companion tests remain required.

The separate [real signed-receipt qualification](../tests/Fixtures/Attestation/README.md) passed on GitHub-hosted Windows using a synthetic package, exact-commit reusable producer, full-SHA-pinned actions/attest v4.1.0, actual Sigstore v0.3 bundle, GitHub CLI 2.97.0 and pinned custom trust roots. The actual `verificationResult` certificate/predicate fields matched the toolkit contract. Real verification rejected wrong predicate/signer/source identities and changed ZIP bytes. `AttestationContract.Tests.ps1` retains regression coverage using unmodified actual verifier output, with negative run/attempt checks. Fixture regression assertions do not substitute for signing/cryptographic verification.

`.github/workflows/receipt-qualification.yml` uses only reserved `v9999.9999.9999-dev.*` synthetic tags, explicitly excluded from toolkit build/publication. Each retry uses a new immutable tag. It downloads the exact CLI archive, checks both archive and executable pins, runs `tools/Test-SignedReceipt.ps1` through the same cleared-environment process launcher/arguments/parser as runtime admission, and retains nonsecret package/bundle/root/output/hash evidence for 90 days. The durable committed fixture retains the successful run. This job has no deployment credentials, privileged runner or IIS operations. Production infrastructure still independently authenticates and protects its own verifier and trust roots. Private/Enterprise signing and consumer/privileged-runner/live-host integration are not qualified by this public-repository result.

**Actual Windows Server 2022/IIS qualification remains NOT RUN.** Start with the [seven-check real-IIS procedure](iis-verification.md) under explicit host/application authorization. Actual lifecycle, independent identity/access, service-profile key continuity, TLS, reboot/storage faults and consumer acceptance require observed evidence. [Qualification tools](../tests/Qualification/README.md) support separately scoped checks; their scenario catalog is not a mandatory release campaign.
