# Verification

Run `tools/Test-Foundation.ps1 -PesterManifestPath <independently-verified-Pester.psd1>` on Windows with the pinned PowerShell 7.6.6 and Pester 5.7.1. It checks syntax, schemas, module exports, dependency inventory and the complete offline/Windows suite. Hosted PR CI has no deployment credentials or privileged IIS runner.

Tests cover strict package/approval contracts, malicious archives, physical paths and access checks, exclusive locking, deployment, fresh-readiness NoOp, configuration restart, partial replacement, retained backups and all three explicit recovery modes. File/state/backup operations use owned NTFS fixtures; IIS and independent-identity observations are synthetic. Qualification-tool tests also use actual loopback Kestrel and current-user DPAPI. Passing these tests does not qualify a real IIS host or service token.

Application-specific compatibility and consumer adoption acceptance remain application-owned; the shared orchestration and packaging contracts below now have toolkit-owned offline tests. For an authorized representative payload, measure deployment, backup and replacement time against the operation budgets in [public contracts](contracts.md). Local synthetic-IIS timing does not establish Server 2022/IIS throughput.

`AutomatedDeployment.Tests.ps1` covers centralized tag classification, protected standing policy, source/build/package mismatches, malformed or substituted identity, successive admission and NoOp, fresh same-tag builds and source binding, identity conflicts, downgrade protection, revocation, interrupted publication, locking and independent recovery authority. It uses actual owned NTFS files and deployment state with synthetic IIS/identity observations. No signing interface is mocked or required. Existing lifecycle/backup/readiness/companion tests remain required.

The shared release additions use compact synthetic SSRS Web, Polaris OIDC, Favorite Authors and ASAP cases; no consumer repository, deployment script suite or production database is copied or executed:

- `SharedApplicationRelease.Tests.ps1` and `SharedReleasePublisher.Tests.ps1` cover current reviewed same-repository PR heads, protected snapshots/test tags, stale review/moved-tag/trusted-code rejection, exact producer job/run/attempt/artifact transport, completed-release preservation, conflicting assets and publication races. HTTP calls use deterministic offline boundaries, including redirect credential stripping.
- `SourceAdmission.Tests.ps1` exercises standing schema 2, verified evidence schema 2 and generated approval schema 3 through real owned NTFS state with synthetic IIS. It covers successive snapshot ordering, explicit test/PR scopes, branch mismatches, direct retry revocation, SemVer/snapshot separation and identical-artifact reclassification after PR integration.
- `ApplicationWorkflow.Tests.ps1` covers immutable shared/caller identity, protected routing, qualified artifact selection, disabled production, superseded automatic snapshots and authorized explicit redeployment. It does not establish that a real organization's runner/environment controls or OIDC handoff have been exercised.
- `WorkflowEntrypoints.Tests.ps1` executes the actual workflow script for release publication, deployment admission, disabled/superseded results and a ValidateOnly engine handoff through mocked infrastructure. It checks real imports, parameter/environment wiring, source/producer/artifact verification, ZIP bytes and publication orchestration with offline GitHub responses. It also executes the byte-identical package script in a clean committed machinery fixture, including real distribution and ZIP production, both with and without a NuGet lock; invalid inputs cannot advertise a package. Network and privileged host boundaries are mocked. These tests do not execute consumer builds or qualify actual GitHub/host controls.
- `Packaging.Tests.ps1` accepts conventional, ASAP WebDAV, Favorite Authors Production-argument and custom application IIS configuration without rewriting bytes. `Archive.Tests.ps1` and existing path/inventory tests retain malformed/DTD/entity/size, tampering, traversal and physical-containment rejection. `Contracts.Tests.ps1` checks V1's required lock digest and V2's explicit nullable lock evidence against both the parser and standalone schemas.
- `HookPackaging.Tests.ps1`, `Hooks.Contracts.Tests.ps1` and `ApplicationHooks.Tests.ps1` verify separate exact hook/support inventories, no-hook full-cycle repeats, four lifecycle stages, FA BeforeStop repeats/failure before IIS effects, ASAP AfterStop and distinct plan-only execution, malformed/crashed/timed-out hook handling, sticky external-state uncertainty, helper quiescence and independent recovery authority. Synthetic hooks stand in for application-owned SQL/DACPAC/Hangfire logic; tests contact no database or IIS host.

Shared routine packages use contract 2 and intentionally rerun hooks and restart IIS on exact repeats. Existing package-contract-1 NoOp/recovery and manual approval tests remain required. Prerequisite-validator PR #3 is independent read-only work; its eventual diagnostics neither replace these negative tests nor authorize a deployment.
