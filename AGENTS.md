# Repository guidance

This repository contains Clc.Deployment, its ASP.NET Core companion, and shared GitHub release workflows. Before development or operational work, read [README](README.md), [contracts](docs/contracts.md), [deployment](docs/deployment.md), [toolkit acquisition](docs/installation.md), [setup](docs/setup-guide.md), and [IIS verification](docs/iis-verification.md).

- Support Windows Server 2022 x64, stable PowerShell 7.6.6 or later within 7.x, .NET 10 in-process IIS hosting, and a dedicated site, root application, and one-worker pool.
- Initialization previews or creates a stopped, unbound site and pool with automatic startup disabled. Use native ProgramData and one `clc-<application-id>` root per server. Refuse existing unowned or partial installations. Keep DEV and Production on separate dedicated servers.
- GitHub repository permissions, protected tags, protected master history for Production, and runner/workflow restrictions authorize releases. Verify exact artifact bytes and application, target, source, and tag against trusted workflow metadata. Use an immutable toolkit checkout or versioned distribution. Archive metadata alone cannot establish authenticity.
- Keep IIS bindings, certificates, accounts, credentials, application configuration, keys, logs, and dependencies administrator or application owned. Keep runtime privileges separate and verify effective access. Validators run elevated and must be read-only, bounded, and safe for that execution model.
- Serialize deployment and recovery using the held target file lock. Persist intent before effects, verify backups, reject unexpected paths and bytes, and require exact readiness before recording success. Preserve failed evidence. Recovery is explicit and applies to application files only.
- Keep commands, contracts, examples, and regression tests aligned. Verify local changes, exact tool versions, and the full diff. Use the integration branch `master` and a `codex/` branch. Commit, push, and open a PR when requested. Merging requires explicit authorization.
- Real IIS, identity, database, and consumer work needs explicit scope. SSRS Web and other consumer repositories remain outside toolkit changes. Record real-host and consumer acceptance as NOT RUN until actually exercised.
