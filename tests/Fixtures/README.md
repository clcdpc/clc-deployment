# Synthetic foundation fixtures

Every JSON record here uses invented identities, zero source/digest declarations, an example machine UUID, synthetic paths and the reserved `synthetic.invalid` domain. These records are untrusted shape examples, never approvals or enrolled host policy. No credentials, private configuration, copied consumer code or published application artifacts are present.

`release-manifest.json` describes only the generated probe bytes in `Support.ps1`. Tests create all ZIPs, malicious headers, source trees, links and sentinels in isolated `clc-<32-hex-guid>` directories directly under the process's Temp parent. Cleanup and native harness guards require that exact owned form. Hosted verification selects the short runner-owned parent through process-local TEMP/TMP; local verification likewise needs a short owned parent. The full GUID child and synthetic `c` control-state child must fit T3's 71-character control-state root budget for the longest two-counter GuardStop leaf, without relaxing the 240-character final-path contract. Parent tests and guarded native harnesses use the same mocked layout; actual NTFS/handle/state/process mechanics remain real, and this is not installation qualification. A separate bounded runspace exercises the unmocked production location resolver, including source-checkout refusal and fixed versioned paths. Overlong-source tests derive an exact 241-character path so fixture naming cannot silently weaken their negative case. The DLL fixture is inert text. Script-shaped exclusions contain sentinel text and are rejected before output. Test helpers execute only as test infrastructure.

Native fixtures exercise real NTFS identities, file sharing, junction ancestors/descendants, hard links, named streams, subst and 8.3 aliases. If automatic short names are unavailable, the test attempts an isolated file short-name assignment; it never changes a system volume setting. Unavailable capabilities are reported as skips and fail `Test-Foundation.ps1`, including on hosted Windows. Cleanup validates the resolved task directory and removes only its own links/mapping.

The suite uses small injected internal stream/ZIP limits plus actual 4 MiB JSON, 240-character paths, 20,001-entry archives, a compressed expansion bomb and a 68-file/8 MiB publish fixture. Production-size limit rejections use inconsistent declared headers without creating gigabyte payloads. T3 public Invoke/Restore tests run actual staging/backup/replacement/recovery/state operations against those owned fixtures; selected application validation and IIS helpers remain synthetic harmless processes. Production HTTPS tests use test-owned loopback peers without trust-store changes. Actual IIS, independent-identity protections, privileged host/storage/runtime qualification and consumer acceptance remain T4/later gates. The unreleased recovery shape requires nullable retirementIntentSha256; older incomplete records reject. The private file-effect fixture adds exact temporary-file identity evidence and grants no execution authority.
